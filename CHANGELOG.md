# Changelog

## Unreleased

- `--search` now accepts a value wrapped in a byte order mark (U+FEFF), as its argument check already did. The check stripped the mark but reading the setting did not, so such a run passed the check and then failed with 'Search mode must be "on" or "off"'.
- When a completed ChatGPT run's cleanup is retried after its tab was closed outside Alcuin, it now deletes the session's staged copies of the attached files and clears the session's `cleanupWarning`, as cleanup does when Alcuin closes the tab itself. It marked the cleanup done but kept the copies.
- Linux on aarch64 (64-bit Arm): each release now carries `alcuin-aarch64-unknown-linux-gnu.tar.gz`, built and smoke-tested on an Arm runner, and `install.sh` installs it on a machine whose `uname -m` is `aarch64` or `arm64`. CI runs the test suite on Arm Linux too.
- When a browser send stays uncertain because the submission witness captured nothing, the error now names the check that refused it: 'commitment is ambiguous (submission-witness-unavailable: unqualified-content)' when the message ChatGPT sent does not carry the prompt's exact text, `unqualified-identity` for its other fields, `expired` and so on. Before, every such refusal read the same.
- When Chrome fails to start, with 'Chrome startup deadline expired' or 'Native Chrome exited before its debugging endpoint was acknowledged', the error now ends with the last lines Chrome printed (`; Chrome stderr: ...`), which say why it never opened its debugging port. They come from `oracle-chrome-stderr.log` in the browser profile, which Alcuin already wrote but no message named.
- A ChatGPT composer pill that matches only the old model-button fallback (`button.__composer-pill[aria-haspopup="menu"]`) no longer outranks the model trigger: the model and thinking pickers take the first selector in their list that matches, not the first match on the page. Before, a run whose composer showed such a pill ahead of the trigger refused the selection with 'composer trigger is ambiguous'. The health guard and the history reader also find the trigger by its `reasoning` navigation target now, as the pickers do.
- One-command installers: `install.sh` for Linux (`curl -fsSL https://raw.githubusercontent.com/yungSNAT/Alcuin/main/install.sh | sh`) and `install.ps1` for Windows (`irm https://raw.githubusercontent.com/yungSNAT/Alcuin/main/install.ps1 | iex`). Each downloads the latest release, or the tag in `ALCUIN_VERSION`, checks the archive's SHA-256 checksum and that `alcuin` runs, then installs `alcuin` and `alcuin-mcp` in `~/.local/bin` or `%LOCALAPPDATA%\Programs\Alcuin` (`ALCUIN_INSTALL_DIR`); the Windows script adds that folder to the user `Path` unless `ALCUIN_NO_MODIFY_PATH=1`. A running `alcuin-mcp` is replaced, not left in place. Both download only over HTTPS (`install.ps1` also from this machine over plain HTTP).
- An API run that Alcuin cannot price, under a `pricing: null` model override or with a response whose cached and written token counts exceed its input, now stores `"cost": null`, and `status`, the session table and the notification show no cost for it. They showed one priced at the full input rate. MCP `consult` and `wait` return that null in `models[].usage.cost`, which their output schemas now allow. A session stored without a `cost` key, as Oracle writes one it could not price, is still priced from the bundled table; one Alcuin wrote before this change is too.
- A project's `.oracle/config.json` is read only from directories your account owns: the search up from the working directory stops before the first one it does not, and a project file another account owns is refused with 'owned by another account'. It went on to the filesystem root, so outside your home folder a file another account put in a shared folder such as `/tmp` or a drive root applied to your run, and could switch it to a paid API run or add text to every prompt. The search also stops before your account's own home folder when `HOME` or `USERPROFILE` names another, rather than reading your user config there as a project file. On Windows, a file or folder owned by the Administrators group counts as yours only when Alcuin runs elevated.
- `--route`, `--preflight`, `doctor --providers`, an API `--dry-run` and MCP `consult` with `dryRun` now refuse a base URL other than an `api.openai.com` host, with the reason the run gives ('--reasoning-mode requires the OpenAI or Azure OpenAI Responses API'). They passed such a URL, though every API run through it is refused. An MCP API `dryRun` also resolves the provider route now, so it refuses what the run would, such as Azure without a deployment.
- `--help`, the README and the guides no longer offer a custom `--base-url` or `OPENAI_BASE_URL`, such as a LiteLLM proxy, for API runs: Alcuin refuses an API run through any base URL other than an `api.openai.com` host, as its Pro reasoning needs the Responses API.
- `--max-cost <dollars>`, the `maxCost` config key and MCP `consult`'s `maxCost` refuse an API run before anything is sent when its estimated worst-case cost is more than that many US dollars: its input, by Alcuin's token estimate, at the cache-write rate plus `--max-output` tokens at the output rate. A capped run needs `--max-output` and `--search off`, and a follow-up is refused, as their charges cannot be bounded. The lower of the config's and the run's cap applies. MCP `consult` also takes `maxOutput`.
- When ChatGPT shows that an answer failed to load, the short read of the original tab that follows no longer ends the run with 'Original-target observation did not settle before its deadline' or a storage or lock error, such as 'Atomic publication deadline reached', when a flush, lock wait or page read outlasted what was left of that read. Each check of the tab now has the full command budget, so only a check that fails within it ends the run, and a page read still pending at the end is followed by a fresh tab check. The run then keeps the load failure, so the one same-turn retry and the later harvest still apply.
- An API run's cost prices cached input at a tenth of the input rate and cache writes at 1.25 times it, as OpenAI bills GPT-6 Astra ($1.00 and $12.50 per 1M tokens against $10.00, read on its pricing page on 15 November 2026). Every input token was priced at the full rate before. A response whose cached and written counts exceed its input tokens stores no cost.
- ChatGPT runs log when the answer's response stream ended, beside the completion check: for example `[browser] Stream-end trace: ended 41234 ms after send; fetch looked native; gate confirmed 43000 ms into the wait.` The page takes the time from the browser's Resource Timing entry for that request, never touching the request or response, and keeps only that state, the elapsed time and whether the page's `fetch` looked like the browser's own (advisory: a page wrapper can fool it, and a wrapped `fetch` can misattribute the time). This gathers the evidence needed before the stream end can decide completion.
- Releases are listed on the MCP Registry as `io.github.yungSNAT/alcuin`: the release workflow writes `server.json` for the tag's bundle and publishes it by GitHub OIDC, with no stored secret.
- The failed-run sweep no longer leaves its cursor lock held when another sweep contends for it as the lock is released. Such a lock stayed until the process exited, every later cursor write in that process was skipped as busy, and stderr showed 'Failed-run sweep cursor lock release remains pending'.
- `--help` no longer lists options that Alcuin refuses: `--verbose-render`, the provider-native capture pair and `--retain-hours`. Its verbose form (`--help --verbose`, `--debug-help`) also drops the browser recheck and auto-reattach timings and `--browser-reuse-wait`, and subcommand help hides `--clear` and `--browser-reuse-wait`. Passing one is still refused (#121).
- When reattaching to a session (harvest) finds no Markdown from ChatGPT's Copy button, Alcuin still saves the answer's page text, but now logs that it did and records `captureSource: "page-text"` in the session's harvest, as a live run has since #126. It did so silently before.
- Such a page-text answer is now committed to the target journal as `text`, not `markdown`, so the journal no longer claims Markdown formatting it does not have.
- The MCP tools `consult` and `wait` are titled 'Run an Alcuin session' and 'Wait for an Alcuin session', and `consult`'s description says 'an Alcuin session', replacing 'a Alcuin' (#121).
- Claude Code users can install Alcuin as a plugin: `/plugin marketplace add yungSNAT/Alcuin`, then `/plugin install alcuin@alcuin`. The plugin runs the same `alcuin-mcp` server as the entry `alcuin bridge claude-config --local-browser` prints and adds the `alcuin` skill; the binaries still come from the release.
- A Ctrl-C pressed just after a CLI command starts, such as `alcuin status <id>`, now prints 'Cancelled.' and exits 130 as a later one does. The listener was installed only when its task first ran, so an earlier Ctrl-C killed the process by signal (#128).
- The 'Did you mean' suggestion for an unknown option no longer offers hidden options, such as the refused `--clear` and `--browser-reuse-wait` (#128).
- A receipt read of a retained submission witness checks Temporary Chat twice, not 3 times: it reuses the state the read already checked, so a long conversation's page is walked one time fewer (#135).
- MCP `consult` runs as a task (the MCP Tasks extension, `io.modelcontextprotocol/tasks`) for a client that declares that extension, so the client need not hold the call open whilst the consultation runs. The client polls `tasks/get` for the same result the call returned before and can stop the run with `tasks/cancel`; closing the server cancels it too. Other clients, and every other tool, get the same results as before. The server now advertises the extension, and a `tasks/*` request from a client that has not declared it fails with -32021 (missing client capability) in place of -32601.
- MCP `consult` and `project_sources`, and `alcuin project-sources`, now refuse to run when a `config.json` (the user's or a project's `.oracle/config.json`) cannot be read or parsed, naming the file. The warning reached only the server's stderr, which an MCP client does not show, and the run went ahead without that file's settings: with `OPENAI_API_KEY` set, a browser engine set only in a broken config became a paid API run.
- An MCP `consult` that waits for its answer takes its perf trace only from the server's `ORACLE_PERF_TRACE`. It used the process-wide trace first, so after one traced consult every later one in the same server named its file after both session IDs (`trace.<first>.<later>.json`). A detached MCP `consult` (`waitForCompletion: false`) now does the same; its worker's trace still carried both IDs.
- The MCP server has a `ground` tool, 'Check an Alcuin answer's evidence', so an MCP client can check a saved answer's citations and quotes as `alcuin ground` does. It returns the `--json` report with `sessionId` and `flagged`, sees the sessions `sessions` and `wait` see, and reads a session's files as they are now only inside the server's working directory unless `ORACLE_MCP_ALLOW_EXTERNAL_INPUT=1` is set.
- `alcuin docs check` no longer reads the options on an `npx` or `gh` command line, such as `npx skills add` or `gh attestation verify`, as Alcuin's own; such a line was reported as drift. A line that runs Oracle through `npx` is still checked.

## 0.1.0 (2026-11-12)

First public release. Alcuin is a Rust port of [Oracle](https://github.com/steipete/oracle), made from a private fork that has since been retired; this repository starts a fresh history and carries no upstream changelog.

- CLI `alcuin` and stdio MCP server `alcuin-mcp` for Windows and Linux.
- ChatGPT browser runs in Temporary Chat with model and thinking-tier verification before dispatch, durable sessions and recovery that never resends an uncertain prompt.
- OpenAI and Azure OpenAI Responses API runs, with background mode.
- Optional Grok browser fallback in Private Chat after a qualifying ChatGPT failure.
- Remote bridge (`serve` and client) for running the browser on another machine.
- Agent skill in `skills/alcuin`, added with the Skills CLI.
- Release archives of both binaries for Linux and Windows (x86_64), with SHA-256 checksums and build provenance attestations, and an MCP bundle, `alcuin.mcpb`, for Claude Desktop.
- Compatible with Oracle's `ORACLE_*` settings and `~/.oracle` session storage.
- `serve` prints its access token only when it generates one, adds `--token-file`, compares tokens without early exit, refuses an empty token and answers HTTP 413 `payload_too_large` for run requests over 1,432,704,342 bytes (Oracle's limit).
- File selection fails closed: `.gitignore` rules apply from the root of the repository holding each selected path, a `.gitignore` that cannot be read or parsed is an error, files read into an API prompt or a browser text bundle must be UTF-8 text rather than being garbled (browser uploads and ZIP bundles still send the original bytes), and credential and private-key files are refused by name and skipped in expansion.
- `serve` binds 127.0.0.1 by default; pass `--host` (for example `--host 0.0.0.0`) to accept other machines. It previously bound 0.0.0.0.
- Runs refuse credentials before sending: every selected file, of any type, and the prompt, system prompt and browser follow-ups are scanned for private key blocks and published token formats, and a match refuses the whole run, naming the source, line and pattern but no part of the value. Selections over 1 GiB, non-regular files and files that change after the scan are refused too. `--allow-secret-file` exempts named files for one CLI run; MCP has no override. `SECURITY.md` lists the gaps.
- MCP `consult` and `project_sources` read files only inside the server's working directory: absolute paths, `..` and links that lead outside are refused before anything is read, unless `ORACLE_MCP_ALLOW_EXTERNAL_INPUT=1` is set.
- MCP `sessions` and `wait` see only sessions started in or below the server's working directory, so one project's agent no longer reads another project's prompts, logs and requests; `ORACLE_MCP_ALL_SESSIONS=1` restores every project's sessions.
- `--browser-end-marker` (MCP `browserEndMarker`, config `browser.endMarker`) adds a per-run line to the prompt that the answer must end with. A run whose answer lacks it is saved as `partial` with `response.status: incomplete`, as is an unmarked local 1 or 2 character answer to a prompt of 1,000 tokens or more. Results from `--remote-host` are not size checked: the client has no token estimate, and a remote `partial` means the final result is still being delivered. Prompts without the option are unchanged, a partial run's tab closes as a completed run's does, and retry, reattachment, harvest and recovery do not reopen or rewrite it. An answer from a same-turn retry owes the same marker.
- A foreground or `--wait` browser run saved as `partial` now prints a notice on stdout and exits 1, where it would have exited 0. The partial text stays in the session and any `--write-output` file. `alcuin session <id>` shows the notice and still exits 0.
- MCP `consult` and `wait` return the whole saved answer in `output` rather than the last 4,000 units of the log, which moves to a new `log` field, and `output` is empty until an answer is saved. Their text content follows `output`, falling back to the log whilst there is no answer. Both add `modelSelection` and `thinkingSelection` evidence, and a call forwards at most 64 KiB of log notifications, each line clipped to 8 KiB.
- An explicit `gpt-6-pro` request outranks a saved `browser.thinkingTime`. A per-call `browserThinkingTime` and the `current` and `ignore` model strategies still take precedence.
- The MCP server advertises only what it runs: the `chatgpt_image` tool and `consult`'s `models`, `generateImage`, `outputPath` and Deep Research options are gone, with `ORACLE_MCP_ALLOW_EXTERNAL_OUTPUT` (images and Deep Research were refused before anything was sent, and `models` resolved to the one permitted GPT-6 API model), and `project_sources` says that `add` only previews. Every tool carries MCP annotations: `consult` and `project_sources` reach ChatGPT (`openWorldHint`), `sessions` and `wait` only read local sessions (`readOnlyHint`).
- Every MCP tool refuses input keys its schema does not declare, and each input schema says so with `additionalProperties: false`. `project_sources` and `sessions` previously ignored undeclared keys, so a key such as `maxFileSizeBytes` reached the run.
- File sections in rendered prompts and bundles keep every line that ended, dropping only the final line ending, so a file ending in a whitespace-only line (as a diff can) arrives whole.
- The answer wait keeps polling for up to 10 command budgets when a page read after the send times out or throws, instead of failing the run while ChatGPT is still answering. A privacy refusal or a closed connection still ends it at once.
- A tab retirement that has reached its outcome always records it: a slow disk write at the end of the 5 s budget no longer reports a false cleanup failure and leaves the record undecided, with the tab already closed.
- Alcuin closes its ChatGPT tab once the answer is saved even when the tab's live text has drifted from the saved answer; identity, ownership and completion are still checked, and the mismatch is logged. It also closes the tabs that failed runs created: only a page that still carries the run's own claim, on the same browser instance, once the run and any parent consultation have ended and its controller has exited or is the current process. Recovery then reports the tab as closed after the run failed.
- A first ChatGPT attempt that failed before anything was sent (a closed CDP connection, a command queue timeout or an unconfirmed picker cleanup), and whose dispatch record is absent or never started, is retried once in a fresh tab. A failed run's tab stays open for 60 minutes when its prompt may have been sent or its answer would not load, so the answer can still be read; a run that cannot reach the browser says that nothing was sent; and a configured `remoteChromeLauncher` starts once when a loopback `remoteChrome` endpoint refuses connections.
- An answer wait reached just after the bounded original-target observation ended reports the answer deadline, as it does just before: a stall there no longer replaces that failure with an untyped error that withholds the Grok fallback.
- A browser slot held by an exited controller whose tab allocation failed before it recorded a target is freed. Nothing can have been sent through such a lease, yet it kept its slot for good, so later runs timed out waiting for a free slot.
- `bridge host` installs its SIGTERM and Ctrl+C handlers before the host can answer in the foreground, or before it reports ready in the background, so a stop signal sent at that point shuts it down cleanly. Such a signal previously could kill the process before shutdown.
- A turn holding only ChatGPT's terminal 'Thinking failed' state ends the run as a generation failure, with or without a Retry control, instead of being saved as the answer. An answer that quotes the phrase is still an answer. Reattach and harvest now treat any failed turn as no answer; they previously saved its text.
- A stray login link no longer fails a signed-in page in the login check or `browser-health` once the session and the app both prove sign-in. An auth page, a signed-out session or a login link with weaker evidence still fails.
- Warning codes joined by separators, such as `rate_limit_exceeded` and `cloudflare_challenge`, are collected and classified like their spaced wording.
- A failed ChatGPT page load is retried once in the same tab before the run reports it; nothing has been sent at that point.
- An owned single-turn ChatGPT run whose answer failed to generate or would not load retries that turn once through the page's own Retry or Try again control, after the read recovery finds nothing and unless ChatGPT shows a rate-limit or account warning. The user message is not sent again, though ChatGPT does generate the turn a second time; `providerRetry` in the session records the retry before the click, so a rerun of the wait cannot spend it twice. Reloading or reopening a Temporary Chat loses it, so the failed page is the only way back.
- ChatGPT's 'This response couldn't load' notice stays a load failure when a Retry sits beside it, and a harvest no longer saves that notice as an answer or completes its session.
- A remote browser that fails the sign-in check gets one recheck on a reopened page 5 seconds later, before anything is sent, then fails with the same message. A signed-in session has failed that check for moments at a time. Failed checks now reach the session log without `--verbose`.
- `alcuin ground <id>` checks a session's saved answer against the files it sent and its prompt: it flags `path:line` and `path:start-end` citations past the end of a sent file or naming a file not sent, and quoted spans of 8 or more characters that no sent file contains, reading either side of a sent unified diff and skipping fenced code. It reads the bytes the session saved (the API request, or the browser prompt and staged uploads) and falls back to the files as they are now, saying so, when no copy remains. It exits 1 when it flags anything, 0 when clean and 2 when it cannot check. Ported from Ryan Duguid's TypeScript fork, where `ground` took the answer and file paths.
- ChatGPT runs no longer fail with `complete-prompt-mismatch` after ChatGPT has stored the prompt. From 7 November 2026 ChatGPT puts another element before the stored user message, and the commit check, inspection and retirement looked only in the old place. They now take the one element that carries the message; 2 such elements are still ambiguous.
- A fresh browser run may ask for Extra High (`--browser-thinking-time extra-high`, MCP `browserThinkingTime` or a saved `browser.thinkingTime`): it selects and verifies GPT-6 at Extra High without trying Pro, so routine runs can leave a capped Pro allowance for the runs that need it. Fresh runs previously had to try Pro first, and a saved `extra-high` setting made them fail. Pro requests are unchanged, and other tiers are still refused.
- When ChatGPT's page holds no stored copy of the new user message, the commit check now fails with `complete-prompt-source-unavailable` rather than `complete-prompt-mismatch`, which is kept for a stored prompt that differs. A missing copy points at a page change, as on 7 November 2026. Both outcomes stop the run without a resend and are recovered the same way.
- A saved `browser.thinkingTime` or per-call `browserThinkingTime` that is present but not text (a number, list or object) is refused as an unknown thinking time, by runs and by `browser-health`, even when a per-call value would override the saved one. Both read it as absent, so a run silently used Pro and `browser-health` checked Pro.
- `serve` and `bridge host` refuse a client's thinking time other than Pro or Extra High before they create the run's session. They read a non-text value as Pro and refused other tiers only after opening a tab.
- MCP `browserThinkingTime` lists only the tiers a run accepts (`pro`, `extra-high` and the `extra high`, `extrahigh` and `xhigh` spellings), so other values are refused at input validation rather than at admission.
- The `browser-pro-fast-large-run` warning no longer fires on a run verified at Extra High, whether requested or the Pro-unavailable fallback, even when its model name is `gpt-6-pro`.
- ChatGPT runs no longer fail with 'Browser expression failed; result was not accepted.' after sending. From 10 November 2026 ChatGPT keys the conversation view by its local client ID and names the server ID only in the view's history, so the Temporary Chat check never matched the view to the conversation URL and every read after sending was refused. The check now reads that field when the old one is absent.
- A refused browser read now says what refused it. 'Browser expression failed; result was not accepted.' is followed by the first line the page threw, and a Temporary Chat refusal names the failed check, such as 'Temporary Chat binding not found for the conversation view'. The generic message had hidden the 10 November page change. No check is relaxed.
